## 输入与复现

输入：`D:\codex\culture-wall-skilled-4766x2690.png`（欧连/ACH 的正视候选图，4766×2690 像素；它本身不是生产文件）。

复现：先将 `vtracer==0.6.15` 安装到忽略目录 `output/vector-spike/vendor`，再执行 `python scripts/vector-spike.py D:\codex\culture-wall-skilled-4766x2690.png`。输出均在 Git 忽略的 `output/vector-spike/`，包括原裁片、原始 SVG、工作台可导入 SVG 和坐标清单。工具脚本是小样胶水代码，描摹算法复用 [VTracer](https://github.com/visioncortex/vtracer)（MIT），画布沿用 Fabric 7.4。

## 结果

| 对象 | 实测结果 | 结论 |
|---|---|---|
| 标题下的蓝色长装饰线 | 裁片 2660×55；VTracer 输出白底与蓝线两个路径。剔除白底、保留蓝线后得到一个真正的 `<path>`；浏览器成功导入、保存重开、单独导出 SVG（不含 `<image>`）。 | **简单、纯色、无遮挡图形可行**；本次坐标和白底清理由小样脚本针对该图处理，不代表自动找对象。 |
| ACH 字样附近裁片 | VTracer 输出 5 条路径、0 个可编辑文字对象。 | **描摹不等于恢复文字**；原文必须以客户文案为准，OCR 只可辅助定位与提醒核对。 |
| 复杂 Logo/装饰组合 | 尚未做语义分割；此图的文字与底色相邻，直接整块描摹会混层。 | 待测。优先使用客户原始矢量 Logo，缺失时才尝试局部分割、人工修正。 |
| 复杂配图/照片 | 该正视候选图没有合适的复杂配图样本。 | 不假造测试结果；目前以独立透明 PNG 为候选输出。 |

验收脚本 `npx tsx scripts/acceptance-vector-spike.ts` 通过：导入一条真实描摹路径、保存重开、导出只含路径的 SVG。`npm run build` 与 `npm test`（33 项）通过。浏览器测试留下一个本地实验项目；未修改旧项目、未部署线上。

## 下一道门槛

1. 取得客户原始 Logo、客户确认的逐字文案和一个含复杂配图的正视图样本。原始素材优先，避免从 AI 图中反向猜测。
2. 对四类对象各做一次人工基准计时：手工提取/重建，与工具辅助流程比较；不仅比较模型运行时间。
3. 对任意图形分割先在本机验证框选→蒙版→透明 PNG 的边缘和遮挡。2GB ECS 不运行 SAM 2；需要 GPU 时先估算国内算力或云 API 费用并取得批准。
4. 仅在稳定降低人工时间后，才将框选/描摹接入网站；失败时保留原图、允许人工上传替换。SVG 文件须确认是路径，不得把 PNG 包入 SVG 冒充矢量。

付款限制：优先本地开源和阿里云等国内可支付服务；不采购海外订阅。阿里云旧“交互式全图分割”已下架，不能作为实施依赖。
