# P0修复验收

结合ZCode体检报告与本站审核，优先修复付费响应丢失、重复收费风险和预算不持久化。仅更新本地版本，未部署ECS。

## 已实现

- 原始响应先保存再清洗；清洗失败可下载原始TXT和免费本地重处理，不自动重新请求上游。
- 账号隔离的任务历史、异步提交、刷新恢复；相同输入/参数复用任务。重付费必须明确确认。
- 调用前持久化预算预占，重启不重置；单并发、每日次数、每日/累计预算及存储前置检查。
- 保留旧版SVG下载，不删除付费资产。1MB仅限制画布插入，完整响应允许更大范围保存/处理。
- 参数变化保留上次结果；修复缓存任务缺少SVG内容导致无法插入画布的问题。

## 验证

- 79项单元/路由测试通过；生产构建通过；git diff --check通过。
- 模拟302浏览器全链路通过：上传、描摹、完整下载、重复请求复用、改参数保留下载、路径插入、保存重开、历史恢复、独立SVG导出。上游模拟调用仅1次，真实付费调用0次。
- 本地后端已重启应用新版。当前每日和累计付费预算均为0，以防负余额继续新增调用；历史恢复下载可用。

## 边界

预算是保守预占，不代表平台实际账单；失败或未知调用需人工核账，不自动退款。旧版已丢失的原始响应不能追回。持久化账本仅支持单Node进程；横向扩容前需升级事务/锁。P1编辑保护、导出一致性及分组等另行处理。
