# 逐元素矢量资产与导出计划

## 当前已做 / 尚未做

生成结果可进入新项目，尺寸、原文、要求、图片自动保存；正视图作为一个未分层图片对象进入画板，空间图仅留参考。已有项目不覆盖。没有自动分层、OCR、描摹或独立元素打包功能。

现有对象类型只有文字、矩形、位图。整体SVG中的文字和矩形是独立对象，图片仍是 `<image>`，不是矢量路径。不能把这些文件统称为纯矢量生产文件。

## 首选实施顺序

1. **明确语义元素**：用欧连案例选公司标题、时间节点、蓝色连接线、底部造型、圆形配图五类。先允许人工框选/上传替换素材，不把一张图片的每个颜色区域误当业务元素。记录位置、尺寸、名称、来源和原文。设备占位独立，不导出成装饰素材。
2. **原始SVG优先**：沿用Fabric的SVG解析能力，增加经过清洗的SVG导入；以组保留复合Logo，允许展开内部路径，而不是当整张图片。服务器拒绝脚本、外链、事件属性及危险嵌入，限制文件大小和路径节点数；保存路径/组/变换数据，不能仅保存渲染PNG。现有图片导入暂不接受SVG，此步骤需扩展数据模型和渲染/导出，不是只改accept属性。
3. **简单位图验证描摹**：候选VTracer，先用Logo和蓝色曲线小样验证。去背景、裁剪、描摹、节点简化、人工修正分开验收。描摹只追踪像素，不能纠正错误Logo、错字或补回遮挡内容。先锁定稳定版本和许可，再接入；不直接将全墙自动描摹作为主流程。
4. **文字恢复**：多模态AI/OCR只建议文字和位置；客户原文为准，人工匹配。保存独立文字对象并在原图上比对。这是图像生成后的编辑恢复，不要求回到“无字生图后拼字”主流程。可编辑文字SVG依赖字体；如需文字轮廓，需取得授权字体并另行验证转曲，不默默改字或替换字体。
5. **混合资产导出**：矢量元素分别导出SVG；复杂照片、山水、渐变配图优先导出PNG，不伪装成矢量。下载ZIP包含整体布局SVG、各元素文件、预览、清单JSON。清单记录mm位置、边界、层级、矢量/位图属性、字体和待修正事项。使用现成ZIP库，先检查维护/许可再选定。

## 工具依据（2026-10-11调研，非本项目已跑通）

- Fabric.js：现有7.4底座，MIT；支持SVG解析与序列化。复用：https://github.com/fabricjs/fabric.js 。本项目尚未实现路径对象持久化和内部对象编辑。
- VTracer：位图转SVG，CLI/Node候选；仓库有近期发布，但新版存在alpha版本，稳定性要小样验证，实际选定版本需检查对应LICENSE。https://github.com/visioncortex/vtracer 、https://github.com/visioncortex/vtracer/releases 。不新增付费服务，不部署GPU。

## 最小验收与阶段边界

第一阶段先完成原始SVG导入/重新打开/内部对象编辑和已有文字、矩形的独立文件导出。第二阶段仅验证一张简单Logo和一段蓝色曲线的裁剪描摹。第三阶段才做语义分层建议和ZIP打包。

每个样本须验证：文件可独立打开；矢量文件不能靠嵌入PNG充数；整体位置按mm还原；保存重开不丢路径/组；源图叠加比较轮廓；文字与原文逐字一致；复杂图片明确标为位图；客户确认仍需修正的内容。未经Illustrator及设计人员实际检查不宣称已兼容生产。

难度：已结构化元素拆文件低；原始SVG安全导入及分组中；简单图形描摹中；全墙自动语义分层、遮挡恢复和准确文字恢复高。首版允许人工选择和替换，不承诺全自动。
