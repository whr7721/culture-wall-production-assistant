# 文化墙真实生产案例分析工作包

这个目录用于在开发 MVP 之前，分析一组真实的“原始需求 → AI 效果图 → 最终生产文件”。它不是生图网站，也不会预设 SVG、CDR、AI、PSD、PDF 或 CAD 中的某一种一定是最终答案。

## 当前研究目标

通过一个已经落地的完整项目，回答六个问题：

1. 效果图与生产文件究竟差在哪里；
2. 中间有哪些人工步骤、各自使用什么软件；
3. 哪些步骤最频繁、最耗时、最容易返工；
4. 哪些适合 AI，哪些适合确定性程序；
5. 实际生产端要求什么文件、结构与质量标准；
6. 第一版 MVP 只解决哪个环节。

## 使用流程

### 1. 收集完整案例

先将需求方交付的案例资料放在任意临时目录中，按 [资料索取清单](templates/01-资料索取清单.md) 检查完整性。不要直接在原始交付目录中开展编辑。

### 2. 初始化案例工作区

在 PowerShell 中运行：

```powershell
Set-Location 'D:\codex\文化墙AI设计工具-交接材料\case-discovery-kit'
.\scripts\Initialize-Case.ps1 `
  -CaseId 'case-001' `
  -CaseName '某文化墙真实项目' `
  -SourcePath 'D:\待分析的案例资料'
```

脚本会：

- 将资料复制到 `cases/case-001/00-原始资料只读`；
- 建立可编辑的 `01-工作副本`；
- 将原始副本中的文件设为只读；
- 生成带 SHA-256 的基线清单；
- 写入访谈、流程、元素追踪、验证和决策模板。

脚本不会修改 `SourcePath` 中的文件，也不会覆盖已经存在的案例目录。

### 3. 开展分析

按顺序填写：

1. `02-分析记录/访谈记录.md`
2. `02-分析记录/人工流程记录.csv`
3. `02-分析记录/当前人工流程图.md`
4. `02-分析记录/元素追踪矩阵.csv`
5. `02-分析记录/效果图与生产文件差异报告.md`
6. `03-技术验证/技术验证记录.md`
7. `04-范围决策/候选功能评估.csv`
8. `04-范围决策/候选功能评分规则.md`
9. `04-范围决策/MVP范围决策书.md`

对原件进行分析前，可检查其完整性：

```powershell
.\scripts\Test-CaseIntegrity.ps1 -CasePath '.\cases\case-001'
```

退出码为 `0` 表示原件未变化；发现新增、丢失或内容改变时退出码为 `2`。

### 4. 锁定 MVP

只有在真实案例中高频、耗时、标准清晰、可继续编辑且能接入实际生产流程的步骤，才进入 MVP。首版只选择一个主流程，不同时承诺抠图、重绘、矢量化、生产检查和多格式交付。

## 目录约定

```text
case-discovery-kit/
├─ cases/                         # 真实案例工作区；默认不提交版本库
├─ scripts/
│  ├─ Initialize-Case.ps1         # 初始化案例、复制原件与工作副本
│  ├─ Update-CaseInventory.ps1    # 生成文件清单与哈希
│  └─ Test-CaseIntegrity.ps1      # 对比基线，检查原件是否变化
├─ templates/                     # 分析模板
└─ tests/Smoke-Test.ps1           # 不依赖真实案例的烟雾测试
```

## 数据与安全边界

- 不把客户隐私、报价、联系方式和真实文件上传到未知在线服务。
- 做 AI 技术验证前，先获得可上传授权或使用脱敏副本。
- `00-原始资料只读` 只用于比对；所有裁剪、转档和实验都在工作副本中进行。
- SHA-256 只能证明内容是否变化，不能替代访问权限、备份和客户授权。
- AI 输出不能因为“看起来相似”就视为可生产，必须在实际设计／生产软件中验证。
